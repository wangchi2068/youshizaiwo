# 《优势在我》机制设计

> 设计原则：**确定性代码管状态，模型只管生成**。
> 本文档的每一条机制都标注了它在运行时里的落点——**默认零代码改动**（本战役与运行时共用一套代码）。

---

## 一、玩家、视角与输入

玩家扮演的不是主任，不是某个科的专家，是**当班主管医生（住院总）**——那个必须把所有人的意见收拢成一句话、然后签字的人。第一人称，输入的是动作、对话、念头。

**没有人负责整个病人，那就是玩家的位置。** 七个科室各管一段，各自正确；把这些正确捏在一起会互相打架，而捏合的责任落在你身上。

运行时落点：`card-neike.json` 的叙述者卡 + `first_mes` 序章；`intro.md` 为剧本存档。

---

## 二、状态变量（全部存在记忆账本里）

运行时已有 `characters / items / relations / plots / notes` 五个账本分区（`src/harness/memory-ledger.ts`）。本作把游戏状态挂成固定 key 的 `notes` 条目，**不改代码**。玩家用 `/state` 查看。

| 状态 | 账本 key | 取值 | 谁在改 | 说明 |
| --- | --- | --- | --- | --- |
| 血糖战线 | `sys-glucose` | 0-100 | 叙述者 | 低 = 血糖失控（激素推高的代价） |
| 免疫抑制 | `sys-immune` | 0-100 | 叙述者 | 越高越压得住原发病，也越容易感染 |
| 骨髓储备 | `sys-marrow` | 0-100 | 叙述者 | 治疗与感染共同消耗 |
| 感染负荷 | `sys-infection` | 0-100 | 叙述者 | 高 = 感染这条线在告急 |
| 循环稳定 | `sys-circulation` | 0-100 | 叙述者 | 心内的战线 |
| 氧合 | `sys-oxygen` | 0-100 | 叙述者 | 呼吸的战线 |
| **病历偏移** | `sys-record-drift` | 0-100 | **旁侧记账模型** | 病历与事实的偏差度（本作签名变量） |
| 家属信任 | `sys-family-trust` | 0-100 | 叙述者 | 谈话与告知的累积效果 |
| 科室影响力 | `sys-factions` | 七个科室 + 护士长 | 叙述者 | 每次拍板后按各方解读此消彼长 |
| 病程记录 | `record-N` | 文本 | **旁侧记账模型** | 一条「病历怎么写的」，允许记歪 |

**关键约束**：这些**不由玩家直接改**。玩家想让某个轴好转，只能通过下医嘱、会诊、谈话——不能点按钮。

## 三、主线推进（已有代码，直接用）

运行时 `director/` 已实现：`arc.json` 的 `phases` 数组按 `unlockKeywords` 命中 + `minTurns` 门槛推进，每回合把 `【主线·第 N 幕】当前目标 / 剧情方向 / 本幕基调 / 本幕必发生` 注入 system（`Director.buildDirective()`）。

**本作额外用到两个字段**：

- `autoAdvance: true`（第五幕·夜班）：忽略关键词，回合数达标即强制推进——**夜班躲不掉**，这是刻意的。
- `minTurnsInPhase`（第四幕、第五幕）：按「进入本幕后的回合数」判定，而不是全局累计回合数。只靠 `minTurns` 的话，玩家在前几幕多聊几句就会让全局计数提前达标，导致最该慢慢演的那一幕一进来就被推走。

## 四、签名机制：病历即经文

**一句话**：病历上写的那个病人，和床上躺着的那个病人，永远不是同一个人；而玩家可以亲眼看到自己被写成了什么。

病历记的是**你半夜一个人拍的板**——而它会被写成「经全科讨论后决定」。这个讽刺不需要任何设定铺垫：每个上过班的人都见过「经研究决定」这四个字。

### 4.1 默认实现（零代码改动）

叙述者卡里已写死「病历即经文」规则：每幕至少产出一条病程记录，并如实呈现它的走样：写入账本 `notes`，key 用 `record-<自增序号>`，content 用

```json
{"as":"实际发生了什么", "recorded":"病历怎么写的", "drift":"歪在哪"}
```

偏差方向服从当前影响力最大的科室：内分泌记为「系统性调整」、风湿记为「按计划推进」、感染记为「已排除」、心内记为「生命体征平稳」、护士长记为「家属要求……」、**被绕过的科室则整条消失**。

### 4.2 完整实现（推荐，可选补丁）

要让病历**由旁侧模型自动、每回合、结构化地**产出，只需把记账员的 system prompt 换成「病历模式」。改动点：`src/harness/memory-ledger.ts` 的 `SCRIBE_SYSTEM` 常量，在其 `notes` 段语义后追加：

```
【病历模式·本战役专用】除了上面的账本，你还要额外输出一段「病程记录」：
把本轮发生的事翻译成病历语言，写入 notes，key 用 record-<自增序号>，
content 用 {"as":实际发生了什么, "recorded":病历怎么写的, "drift":歪在哪}。
要求：recorded 必须与 as 有可辨识偏差，偏差方向服从当前影响力最大的科室——
内分泌记为「系统性调整」、风湿记为「按计划推进」、感染记为「已排除」、
心内记为「生命体征平稳」、护士长记为「家属要求……」、被绕过的科室整条消失。
绝不让 recorded 等于 as。
```

### 4.3 第六幕：签字

玩家在第六幕的最后一个动作不是医疗决策，而是**在病历上签字**——可以逐条读，读了也不能改。**能改的那叫事实，不能改的那叫记录。**

## 五、神谕卡机制（复用 decision-card）

运行时 `harness/decision-card.ts` 已提供：模型在重大转折调用 `decide` 工具，弹出 2-4 个候选方向 + 允许自由输入，选择写入 `decisions.jsonl` 留痕。

**触发时机**（只在这两种情形，其余一律靠自由输入）：
1. 多个科室的意见无法同时满足，必须有人让路；
2. 一次决定会不可逆地改变某个战线的走向。

**四个固定方向**：

| 方向 | 含义 | 代价模式 |
| --- | --- | --- |
| 照单全收 | 按某科字面执行 | 该科影响力暴涨，其他轴被挤压 |
| 折中 | 各让一步 | 两边都不满意，效果打折 |
| 压住不发 | 先观察，什么都不加 | 时间流逝，原发病进展 |
| 越级拍板 | 绕过某科自己定 | 被绕过者记恨，后续留痕 |

**无中立神谕**：医嘱一旦落下，各科必须各自解读并各记一条——同一句「先观察」，内分泌记为「暂缓调整」，风湿记为「按计划推进」，感染记为「继续观察」，护士长只说一句「他今天没吃东西」。

## 六、掷骰机制（复用 roll-card）

运行时 `harness/roll-card.ts` 把检定交给用户真随机，模型不得擅改。本作用在**并发症与检查回报**上：

- 夜间急变发生在第几个钟头？（掷骰）
- 输液反应、造影剂过敏、输血反应发不发生？（掷骰）
- 培养回报落在哪一天——刚好你在开会的那天？（掷骰）

**意义**：把「医生并不掌控病程」这件事变成机制。玩家不是故意作恶，只是无法精确控制——这正是「每个人都没错，体系才是问题」的物理基础。

## 七、科室系统（派系）

七科共存，用 `sys-factions` 记录影响力。

| 科室 | 主张 | 上升时 | 下降时 |
| --- | --- | --- | --- |
| 内分泌 | 血糖是一条不能断的链 | 血糖波动被记录、玩家按它调整 | 血糖长期稳定（它反而失去话语权） |
| 风湿 | 原发病不压，一切都是治标 | 免疫指标活跃、玩家用激素 | 感染抬头、被迫减量 |
| 血液 | 够不够格上治疗，先看评估 | 玩家同意先评估 | 被反复催促后强行上马 |
| 感染 | 病原学证据说话 | 出现阳性结果、发热 | 证据被否定、培养阴性 |
| 消化 | 通道不干净，镜子就看不见 | 消化道症状被处理 | 准备过程伤了病人 |
| 心内 | 循环稳不住，什么都白搭 | 出现心律失常、血压波动 | 循环长期平稳 |
| 呼吸 | 这里是历代征战的古战场 | 氧合恶化、影像进展 | 氧合改善 |

第四幕应当让**至少两个科室的影响力此消彼长到对立**——那是玩家亲手制造的分裂。

## 八、AI 使用点清单

| 环节 | 谁生成 | 为什么必须由 AI 生成、写死就废 |
| --- | --- | --- |
| 各科的部署与话术 | 模型 | 七种腔调、七条战线，写死十几条立刻被玩家识破 |
| **病程记录** | **旁侧模型** | **玩家的每个决定都要被「翻译」成病历语言，且允许记歪——这是本作唯一的对手 AI** |
| 神谕卡选项 | 模型 | 选项必须贴着当下的具体情境长出来 |
| 各科对同一医嘱的解读 | 模型 | 同一个事实的四种解读，是一次真实的「观点对撞」 |
| 护士长的台词 | 模型 | 她必须说具体的、可验证的事实，且每次都不一样 |
| 结局文本 | 模型 | 终局由玩家过往所有选择的组合决定，无法穷举 |

## 九、与运行时模块的对应表

| 本作机制 | 运行时模块 | 是否需要改代码 |
| --- | --- | --- |
| 叙述者与九个角色 | `roleplay/character-card.ts` + 组装层 | 否（换卡即可） |
| 世界设定与科室分工 | `roleplay/lorebook.ts`（关键词 + 向量召回） | 否（换 worldbook.json） |
| 六幕主线与强制夜班 | `director/director.ts` + `arc.json` | 否（用 `autoAdvance` / `minTurnsInPhase`） |
| 状态变量 | `harness/memory-ledger.ts`（notes 固定 key） | 否 |
| **病历记歪** | `harness/memory-ledger.ts` 的 `SCRIBE_SYSTEM` | **可选补丁（见 4.2）** |
| 神谕卡 | `harness/decision-card.ts` | 否 |
| 并发症掷骰 | `harness/roll-card.ts` | 否 |
| 前情提要与时间压缩 | `harness/context.ts` | 否 |
| 存档 / 回档 / 世界线 | `harness/worldline.ts` + `store.ts` | 否 |
| 回合配图 | `harness/illustration.ts` | 否（美术方向已换成本作） |

**结论**：整套机制默认零代码改动即可跑；只有「病历自动记歪」这一条需要一处常量补丁。
